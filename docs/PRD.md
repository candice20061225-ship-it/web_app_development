# 產品需求文件 (PRD) - 讀書計畫管理系統（Study Planner System）

## 1. 專案概述

- **背景與動機**：學生在面對繁重的課業與考試時，常會因為缺乏妥善的時間規劃而導致學習效率低落或進度落後。為了幫助學生有效安排時間、追蹤學習狀況，需要一個專屬的讀書計畫管理系統。
- **目標用戶**：高中生、大學生，以及需要自我時間管理與規劃讀書進度的學生族群。
- **核心價值主張**：提供直覺且易用的工具，幫助使用者有效規劃每日讀書進度、隨時追蹤學習狀況，藉由任務管理與進度視覺化，減輕焦慮並提升整體學習效率。

## 2. 功能需求

以下為系統的主要功能與對應的使用者故事：

### 任務新增
- **作為** 一名學生，**我希望** 能夠新增讀書任務（包含科目、內容、預計完成時間），**以便** 我能清楚知道每一天有哪些具體的學習項目。

### 任務列表
- **作為** 一名學生，**我希望** 能夠看到所有讀書任務並依日期排序，**以便** 我能快速掌握近期需要完成的學習重點與優先順序。

### 完成標記
- **作為** 一名學生，**我希望** 能將任務隨時標記為「已完成」或「未完成」，**以便** 我能確實追蹤每一項任務的執行狀態，並獲得完成任務的成就感。

### 行事曆檢視
- **作為** 一名學生，**我希望** 能以行事曆（日期）的方式查看每日的讀書安排，**以便** 我能從宏觀的角度評估整週或整月的學習規劃是否合理。

### 提醒功能
- **作為** 一名學生，**我希望** 系統能在指定時間提醒我尚未完成的任務，**以便** 我不會因為忘記或拖延而錯過預定的學習進度。

### 進度統計
- **作為** 一名學生，**我希望** 能看到完成任務的比例與整體的學習進度統計圖表，**以便** 我能隨時檢視自己的學習成效並進行調整。

## 3. 非功能需求

- **技術限制**：本專案將採用 Flask 作為後端框架，Jinja2 作為前端模板引擎，並使用 SQLite 作為輕量級關聯式資料庫。
- **效能與安全考量**：
  - 系統響應時間：確保頁面加載與任務狀態更新在 2 秒內完成，提供流暢的使用體驗。
  - 資料安全：對使用者輸入進行基本的防呆與 XSS/SQL Injection 防護處理。
  - 響應式設計 (RWD)：系統需同時支援桌面版與行動版瀏覽器，方便學生隨時隨地查看。

## 4. MVP 範圍 (Minimum Viable Product)

### Must Have (必須要有)
- 任務新增功能（科目、內容、預定日期）
- 任務列表展示（依日期排序）
- 任務完成標記（Checkbox 切換狀態）
- 基本的 SQLite 資料庫儲存

### Should Have (最好要有)
- 行事曆檢視（以月曆或週曆模式呈現）
- 進度統計（簡單的圓餅圖或長條圖顯示完成比例）

### Nice to Have (有也不錯)
- 提醒功能（網頁推播或 Email 提醒尚未完成任務）
- 拖曳排序（手動調整任務優先級）
- 學習時數計時器（番茄鐘功能）
